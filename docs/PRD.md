# PRD — منصة توزيع قطع إلكترونية بالجملة

> جاهز للتسليم لأداة برمجة بالذكاء الاصطناعي (Agent-Ready Prompt)

---

## 1. نظرة عامة (Overview)

منصة تجارة إلكترونية غير تقليدية لمتجر **جملة** يبيع قطعاً إلكترونية فيزيائية. الفرق الجوهري عن متجر تقليدي: **لا يوجد تسجيل عام مفتوح للزبائن**. صاحب المتجر ينشئ حساب كل زبون يدوياً ويمنحه بيانات دخول.

**نموذج العمل:** محل جملة يوزّع قطعاً إلكترونية حسب طلبات زبائن معروفين مسبقاً (شبه مغلق).

## 2. الأهداف (Goals)

- تحكم كامل لصاحب المتجر بقاعدة الزبائن (إضافة، حظر، تقييم ثقة).
- تسهيل الطلب والدفع لزبائن الجملة.
- آلية دفع مرنة (Sham Cash، دفع عند الاستلام، دفع مسبق).
- نظام ثقة يحمي صاحب المتجر من الزبائن غير الموثوقين.

## 3. الأدوار (User Roles)

**الزبون:** لا تسجيل ذاتي — حسابه يُنشأ من المالك. يسجّل دخول بالبريد المعطى له. يضيف عنوانه. يتصفح، يطلب.

**صاحب المتجر:** كل صلاحيات الزبون + إنشاء/تعديل/حذف حسابات، حظر، أكواد خصم، رسائل، إرسال سلات تسوق، إدارة منتجات، رؤية الطلبات ومعدل الثقة.

## 4. الصفحات والميزات

### 4.1 واجهة الزبون
| الصفحة | الوظيفة |
|---|---|
| الرئيسية | عرض المنتجات + فلاتر: إكسسوارات، أدوات أساسية، قطع صغيرة، سماعات/كيبوردات/ماوسات |
| تسجيل الدخول | عبر بريد أنشأه المالك، بدون تسجيل ذاتي |
| الإعدادات | تعديل العنوان والبيانات المسموحة |
| الطلبات | تجميع الفاتورة وإرسالها |

### 4.2 لوحة تحكم المالك
| الصفحة | الوظيفة |
|---|---|
| أكواد الخصم | إنشاء وربط بمنتجات/زبائن |
| حظر الزبائن | تعطيل الوصول |
| الرسائل | تواصل مباشر مع الزبائن |
| إرسال سلات تسوق | تجهيز عربة جاهزة لزبون |
| إدارة المنتجات | إضافة، فئة، صور، ميزات، كمية |
| إدارة الزبائن | إنشاء حساب + معرف + بريد دخول |
| قائمة الطلبات | تفاصيل أدناه |

### 4.3 تفاصيل صفحة الطلبات
تُعرض للمالك: بيانات الزبون وعنوانه، تقييمه، و**معدل الثقة** (حقل حساس يظهر للمالك فقط).

## 5. آلية الدفع

1. **Sham Cash + QR:** كود فريد يُولَّد تلقائياً لكل طلب، المالك يرسله مع التأكيد، الزبون يحوّل ويُدخل الكود. حالات الطلب: تم الإنشاء → بانتظار الدفع → تم الدفع → قيد التجهيز → تم التسليم.
2. **دفع يدوي عند الاستلام:** كامل قيمة الفاتورة، بدون خصومات.
3. **دفع مسبق:** قبل التجهيز والشحن.

## 6. صفحة إضافة المنتجات (للمالك فقط)
إضافة منتج + فئة، صور متعددة، ميزات ديناميكية، كمية المخزون.

## 7. نموذج بيانات مقترح
- **User:** id, role, email, address, trust_score (private), rating, is_blocked, created_by
- **Product:** id, name, category, images[], features[], quantity, price
- **Order:** id, customer_id, items[], total, status, payment_method, discount_code, created_at
- **PaymentCode:** id, order_id, code, status, created_at
- **DiscountCode:** id, code, type, value, applicable_products[], applicable_customers[], expiry
- **Message:** id, sender_id, receiver_id, content, sent_at
- **Cart:** id, customer_id, items[], created_by

## 8. ميزات إضافية مقترحة
سجل طلبات سابقة، إشعارات (Email/Telegram/WhatsApp)، لوحة إحصائيات (أكثر مبيعاً، أعلى الزبائن)، سجل تدقيق للإجراءات الحساسة، صلاحيات موظف فرعية (مستقبلاً)، بحث/فلترة متقدمة، آلية استرجاع الطلبات، حد أدنى للطلب (MOQ)، نسخة PWA متجاوبة.

## 9. نقاط تحتاج قراراً
- هل طرق الدفع الثلاث فعّالة من اليوم الأول أم نبدأ بواحدة؟
- كيف يُحسَب معدل الثقة — تلقائي أم يدوي من المالك؟
- هل سلة المالك المُرسَلة قابلة للتعديل من الزبون أم فقط موافقة/رفض؟
- الستاك التقني وقاعدة البيانات (MERN كمشاريعك السابقة؟).

## 10. نظام التصميم (Design System / Theme)

### 10.1 الفكرة البصرية
التصميم مستوحى من عالم لوحات الدارات الإلكترونية (PCB) — ألوان الفايبرغلاس الأخضر الغامق، مسارات النحاس، ولون الحبر الفضي المطبوع على اللوحات. هذا يربط الهوية البصرية مباشرة بطبيعة المنتج (قطع إلكترونية) بدل استخدام قالب عام.

### 10.2 لوحة الألوان (Color Palette)

| الاستخدام | القيمة | الوصف |
|---|---|---|
| خلفية أساسية (bg-primary) | `#10231A` | أخضر-أسود عميق، مثل قاعدة لوح PCB |
| سطح البطاقات (surface) | `#172B20` | أخضر غامق أفتح قليلاً، للبطاقات والحاويات |
| تمييز أساسي (accent-copper) | `#C17A4D` | نحاسي/لحام — للأزرار الأساسية والروابط والحدود المميزة |
| نجاح/متوفر (accent-mint) | `#6FCF97` | أخضر أثر الدارة النشط — لحالة "متوفر"، "تم الدفع" |
| تنبيه (accent-amber) | `#E0A458` | لأكواد الخصم، تنبيهات المخزون المنخفض |
| خطأ (accent-red) | `#C1473D` | لحالات الحظر، فشل الدفع، إلغاء الطلب |
| نص أساسي (text-primary) | `#EDEAE0` | أبيض دافئ، كحبر السيلك سكرين على PCB |
| نص ثانوي (text-secondary) | `#A9B0A6` | رمادي مائل للأخضر، للنصوص المساعدة |

> ملاحظة: يجب أن يعمل النظام في وضعي فاتح وداكن. الداكن هو الافتراضي (الأقرب لهوية PCB)، والفاتح نسخة مقلوبة بخلفية بيج فاتحة دافئة (`#F3F1E9`) وألوان نصوص/حدود معكوسة من نفس النسب، مع الحفاظ على النحاسي والمينت كألوان تمييز ثابتة.

### 10.3 الطباعة (Typography)

- **العناوين (Display):** `Space Grotesk` — خط هندسي تقني، يُستخدم بحسم في العناوين الكبيرة وأسماء الفئات فقط، وليس في النص العادي.
- **النص الأساسي (Body — عربي/إنجليزي):** `IBM Plex Sans Arabic` (أو `Cairo` كبديل) للعربية، مقابلة بـ `Inter` للاتيني — نفس الوزن البصري للحفاظ على الانسجام بين اللغتين.
- **خط الأداء (Utility/Mono):** `JetBrains Mono` — للأرقام التسلسلية (SKU)، الأسعار، أكواد الدفع والخصم، ومعدل الثقة. يمنح شعور "لوحة مواصفات فنية" ويسهّل مسح الأرقام بصرياً.
- درجات الوزن: عادي (400) وشبه بارز (500) فقط — بدون أوزان ثقيلة تكسر الطابع التقني الهادئ.

### 10.4 التخطيط (Layout Concept)

- شبكة منتجات أشبه بـ"صناديق قطع" (parts bins) — بطاقات مربعة الحواف الحادة قليلاً (radius صغير، وليس دائرياً بالكامل)، بزاوية علوية-يسرى بلون نحاسي تشبه "لحام السطح" (solder pad accent).
- شريط الفلاتر (الفئات الأربع) يظهر كـ"حزام أدوات" أفقي ثابت أعلى الصفحة.
- خطوط فاصلة بين الأقسام تُرسم كخط منقّط رفيع بلون النحاس، يحاكي مسار دارة (circuit trace) بدل خط فاصل عادي.
- يجب دعم RTL بالكامل (الواجهة عربية أساساً) — كل المسافات والأيقونات والاتجاهات تُعكس تلقائياً في وضع RTL.

### 10.5 العنصر المميز (Signature Element)

خط دارة منقّط (animated circuit trace) يربط بصرياً بين عناصر السلة وزر إتمام الدفع، ويكتمل كدارة مغلقة (تُضاء بلون المينت الأخضر) عند نجاح عملية الدفع — يربط اللحظة التفاعلية الأهم (إتمام الطلب) بهوية المنتج نفسه (دارات إلكترونية).

### 10.6 قواعد تصميم عامة (Design Rules)

- **البساطة أولاً:** لا تدرجات لونية (gradients)، لا ظلال قوية، لا تأثيرات نيون — أسطح مسطحة نظيفة فقط.
- **التباين:** يجب أن يبقى النص مقروءاً في كلا الوضعين (فاتح/داكن) — لا نص أسود صرف أو رمادي عام فوق الألوان المميزة؛ استخدم الدرجة الغامقة من نفس عائلة اللون.
- **الحركة:** حركة واحدة موجّهة فقط لكل تفاعل (مثل إكمال الدارة عند الدفع) — تجنّب التأثيرات المتناثرة أو الزخرفية.
- **إمكانية الوصول:** حلقات تركيز (focus rings) واضحة على كل عناصر الإدخال، دعم قارئ الشاشة، احترام إعداد "تقليل الحركة" في المتصفح.
- **الاستجابة (Responsive):** الأولوية للموبايل نظراً لطبيعة الزبائن (تجار قد يطلبون من الهاتف)، مع نسخة PWA لاحقاً كما ورد في الميزات المقترحة.
- **الاتساق:** أي لون جديد يُضاف مستقبلاً يجب أن يُشتق من نفس المنطق (ألوان PCB/النحاس)، وليس لوناً عشوائياً يكسر الهوية.

## 11. تعليمات ملخّصة للـ Agent

- ابنِ النظام بصلاحيتين: `owner` و `customer`، بدون تسجيل ذاتي للزبائن تحت أي ظرف.
- اجعل `trust_score` حقلاً محمياً يظهر فقط في استعلامات المالك.
- صمّم `Order` و `PaymentCode` لدعم توليد كود دفع تلقائي لكل عملية Sham Cash.
- اجعل الفئات قابلة للتوسعة من لوحة التحكم دون تعديل الكود.
- طبّق نظام الألوان والطباعة في القسم 10 حرفياً كمصدر واحد للحقيقة (design tokens)، وادعم RTL بالكامل ووضعي الفاتح/الداكن.
